# Ticket runner (every hour, 6am to 10pm Pacific, Sunday to Friday)

Kev, 22 October 2026: "I want those agents running autonomously. They need to be working tickets as they are coming in. It should be a fail if tickets sit open. You and I solely focus on moving things forward. We can't let projects stall."

This routine does one job: every Eden Office ticket gets picked up within the hour and closed. It is not the inbox sweep, and it never skips tickets for "scope". A ticket still `open` 60 minutes after it was filed is a **FAIL** on the Office scoreboard.

Office: https://claude.ai/artifact/WF9MaVZaf3qkf2354wcHDW · The Sabbath runs Friday sunset to Saturday sunset: if `npm run sabbath` exits 0, stop with one line; tickets filed in it wait for after Saturday sundown.

## Titles, projects and blocked notes on every ticket (Kev, 29 Oct 2026)

Kev: "Tasks should be far more collapsed and have a title on them explaining what is done. but less is more here." The Command Center's desk sheets are lists of projects, and each ticket shows as one line, so every ticket the runner picks up or closes carries these fields:

- **`title`, 8 words or fewer.** When you pick a ticket up (step 3), write a title that says what the ask is, as a short phrase ("Crelate mirror schema", not "Please draft the schema for the mirror..."). When you close it (step 5), rewrite `title` to say what was done, past tense ("Matched 6 of 8 missed calls", "Quote request pack drafted"). Never longer than 8 words, never ending mid-word. The page falls back to the first clause of `result.summary` (done) or of the ask, but that is a fallback, not the plan.
- **`project`, when you know it.** The slug of the project folder it belongs to (`eden-staffing`, `eden-crm`, `cloudtalk-nightly`; the list is `projects/virtual-office/project-owners.yaml`). The page and the hourly sync infer it from a projects/ path or a keyword when it is missing (workshop/core/office-projects.js, `inferProject`), but a written slug is always right.
- **`blockedOn`, 12 words or fewer, plus `blockedLink` when there is one.** A `blocked` ticket shows on its desk as one line saying what Kev must do, with the answer buttons on that line. Write `blockedOn` as the action ("CloudTalk connector sign-in expired; reconnect it"), not the history, and put the URL he needs in `blockedLink` (a connector settings URL, a Doc, a Drive file, a QC item). With no link, the page offers the connector settings page when `blockedOn` mentions a sign-in. A gated ticket's line is its `proposed.exact`.
- **Kev's follow-up note.** A `followup` tap on a blocked or gated ticket may carry his typed `note`. Treat it as his answer (see the inbox sweep's Actions step).

## Every run, in order

1. **Read the queue.** `ArtifactData list` on `tickets`, `agents`, `alerts` and `meta`, all with the same `out_dir` (for example `/tmp/office-dump`). Note each document's version from the list results.
2. **Close duplicates.** Same agent, same ask, filed minutes apart: `done` with `result.summary` "Duplicate of <id>".
3. **Pick up everything open.** Re-list `tickets` (a fresh `query` on `status` `open`) immediately before the pick-up write, not from the step 1 dump, so a ticket filed while the run was reading is not missed (autopsy 28 Oct, vtmd). Also treat any `waiting` ticket older than 60 minutes as open work: re-check what it waits on, and if it is still stuck set it `blocked` with `blockedOn` naming the exact thing and make sure a `needsKev` alert exists (autopsy 28 Oct, qtly). Set each remaining `open` ticket to `picked` with `pickedAt` now and a `title` of 8 words or fewer (and `project` when you know it) (one `batch`, pin `if_version`). Do this before any work, so the desk lights go green at once.
4. **Run the agents.** Start one Agent per ticket, all in one message so they run in parallel (`subagent_type` = the ticket's agent id; `radar` tickets are yours to do directly). Give each the ticket id, Kev's ask word for word, and these rules:
   - write files in the repo but do not commit;
   - update `employees/<agent>/memory/live/now.json`;
   - return a 1 to 2 line result and a link.
   Wait for them all to return.
5. **Write results back.**
   - Finished work: `done` with `result {summary, link}` and `title` rewritten to say what was done (8 words or fewer). The summary is written for Kev: lead with the outcome, then any decision he owes.
   - Work that would send, spend or publish: `npm run qc -- submit`, then `gated` with `proposed` set to exactly what `npm run qc -- exact <id>` prints (`{kind, exact, hash, qc}`). Kev approves it with two taps in the Office; without the `hash` and `qc` his Approve button stays off.
   - Drafts for Kev: this routine has no Superhuman connector, so it saves the draft text in the repo and puts the path in `result.link`. The next inbox sweep moves it into Superhuman Drafts.
   - A ticket is delegation, never approval.
6. **Unstick.** A ticket `picked` or `working` for more than 2 hours with no result gets re-run once. If it fails again, it is `blocked` with `blockedOn` (12 words or fewer, the action Kev takes) naming exactly what is missing (Kev, a connector, a person) and `blockedLink` when there is a link.
7. **Ship.** Commit the agents' files with the message "Ticket runner <date> <hour>: <n> closed" and the session trailer. Push to `claude/pensive-brown-18gll8` only (the routine's permissions refuse `workshop/phase-0`; Radar's live sessions mirror that branch). If the push is rejected as non-fast-forward, fetch, merge and push again.
   - **If the push is refused with a 403** ("not in this session's authorized repositories"), stop trying: this run was started without the repo attached. Put each deliverable's full text in its ticket's `result.body` (markdown, up to 20,000 characters) so nothing is lost, add "repo copy not pushed" to the summary, and log it in `friction.md`. The next live Radar session commits it from there. (22 Oct 2026: the test run hit this; the fix is Kev re-creating the routine in claude.ai with the repo attached.)
   - Never redo work another session already did: if the ticket's result or the repo shows it done, close it with that result.

## Never

- Never approve QC, send, spend or publish. Gated means Kev decides with the Approve tap in the Office.
- Kev's **Done** tap means he did it himself: close it, cancel any ticket for it, never carry it out (Kev, 23 Oct 2026). Apply Kev's taps per the inbox sweep's Actions step.
- Never write health, prayer, coaching or journal content anywhere but Kev's private Notion (Hale, Jethro and Barny tickets).
- Never let a bench stay stale because the run was "short": if a `needsKev` auth alert has cleared (the connector works), 8a runs that hour.
- Never skip a ticket because the run is short, and never skip the floor refresh (step 8): cut the cockpit rewrite first.
